# Phase 1 Data Model: HTTP API for the Application Pipeline

No new domain entities (spec.md Key Entities) — this feature adds HTTP request/response shapes
that wrap features 001/002's existing `Command`/`Event`/`ActivePipelineEntry` types one-to-one.

## Request bodies (mirror each command's `data`, per feature 001/002 `contracts/`)

| Endpoint | Request body | Source shape |
|---|---|---|
| `POST /applications` | `{ company, role, location, salary?, employmentType, bonus?, benefits }` | `SubmitApplication` (002) |
| `POST /applications/:applicationId/interviews` | `{ round, date }` | `ScheduleInterview` (001) |
| `POST /applications/:applicationId/interviews/outcome` | `{ round, outcome }` | `RecordInterviewOutcome` (001) |
| `POST /applications/:applicationId/offer` | `{ amount, deadline }` | `ReceiveOffer` (001) |
| `POST /applications/:applicationId/offer/accept` | *(empty)* | `AcceptOffer` (001) |
| `POST /applications/:applicationId/offer/decline` | *(empty)* | `DeclineOffer` (001) |
| `POST /applications/:applicationId/withdraw` | *(empty)* | `WithdrawApplication` (001) |
| `GET /applications/active` | *(none — query)* | — |
| `POST /ghosting/check` | *(empty)* | — |

`:applicationId` is the stream ID generated by `POST /applications` (see research.md).

## Response bodies

| Endpoint | Success response | Notes |
|---|---|---|
| `POST /applications` | `201 { applicationId }` | New stream ID (FR-001, Acceptance Scenario 1) |
| `POST /applications/:id/interviews` | `200 {}` | |
| `POST /applications/:id/interviews/outcome` | `200 {}` | |
| `POST /applications/:id/offer` | `200 {}` | |
| `POST /applications/:id/offer/accept` | `200 {}` | |
| `POST /applications/:id/offer/decline` | `200 {}` | |
| `POST /applications/:id/withdraw` | `200 {}` | |
| `GET /applications/active` | `200 ActivePipelineEntry[]` | Same shape as feature 001's `getActivePipeline()`, JSON-serialized |
| `POST /ghosting/check` | `200 { ghosted: string[] }` | IDs of applications ghosted by this check (may be empty) |

## Error response shape (shared across every endpoint)

```text
{
  error: string   # short machine-readable reason, e.g. "ApplicationNotFound",
                   # "InvalidRequest", or the guard's message (e.g. "RoundOutOfSequence")
  message: string  # human-readable detail
}
```

| Status | Meaning | Source |
|---|---|---|
| `400` | Malformed/missing required input | Fastify JSON Schema validation (FR-011) |
| `404` | `applicationId` has no prior events | `state.status === "NotSubmitted"` pre-check (FR-012) |
| `409` | Guard violation on an existing application | `IllegalStateError` from `decide()` (FR-010) |

No application state changes on any of the three error paths above (FR-013) — 400 and 404 never
reach `decide()`/`DeciderCommandHandler`, and a `409` means `decide()` threw before returning
events to append.
